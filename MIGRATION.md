# Migration: C4-Auto to AutoDoc

AutoDoc is the new name for the automated C4 documentation CLI formerly published as `@jonverrier/c4-auto`.

## Package and CLI

| Before | After |
|--------|-------|
| `@jonverrier/c4-auto` | `@jonverrier/auto-doc` |
| `c4-auto` CLI | `auto-doc` CLI (preferred) |
| — | `c4-auto` CLI alias still available in v1.0.0 |

## Upgrade steps

1. Update `package.json`:

```json
{
  "devDependencies": {
    "@jonverrier/auto-doc": "^1.0.0"
  },
  "scripts": {
    "generate-docs": "auto-doc --dir ./src --files \"*.ts\" \"*.tsx\" --one-month --c4component --c4context --rollup"
  }
}
```

2. Replace `c4-auto` with `auto-doc` in npm scripts and CI (or keep `c4-auto` temporarily — it remains a compatibility alias).

3. No change required for generated artifact filenames (`README.StrongAI.Component.md`, etc.) or datestamp format (`<!-- Generated by StrongAIAutoDoc YYYYMMDD -->`).

## New in v1.0.0

### Rollup design context

When using `--rollup`, AutoDoc includes human-authored design intent as read-only prompt context:

- Auto-detects `Design.md` or `DESIGN.md` at the scan root or its parent directory.
- Override with `--design-file <path>`.
- Design files are never modified.
- Rollup regenerates when the design file is newer than the existing root rollup.

Example:

```bash
auto-doc --dir ./src --files "*.ts" --one-month --c4component --rollup --design-file DESIGN.md
```
